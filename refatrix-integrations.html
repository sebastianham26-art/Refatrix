전송 이력
끄면 전송 건이 대기함에 쌓이기만 합니다.
수신 연동 — 이 주소로 상대(CRM)가 우리에게 보냅니다. 우리가 보내는 게 아니므로 상대 URL·메서드 설정이 없습니다. 아래 주소와 API 키를 상대 개발자에게 주면 됩니다.
키는 x-api-key 헤더 · ?apiKey= 쿼리 · 본문 apiKey 필드 어디에 실어도 받습니다 — 상대 구현을 기다리느라 수신이 막히지 않게 셋 다 열어 뒀습니다.
키는 서버가 만들고, 발급 직후 창이 하나 뜹니다. 그 창은 「닫기」를 누르기 전까지 사라지지 않으니 천천히 복사해 상대에게 전달하세요 — 닫고 나면 다시 볼 수 없고, 잃어버리면 새로 발급하면 됩니다(그 순간 이전 키는 즉시 막힙니다). 두 키 모두 유효하게 받아 줍니다(어느 쪽으로 들어왔는지는 수신 이력에 남습니다).
키는 서버마다 다릅니다. 여기 넣어 두면 「사용 중인 서버」를 바꿀 때 키도 같이 바뀝니다 — 전환할 때마다 다시 넣지 않아도 됩니다. 헤더 이름이 Authorization 이고 개발자가 Bearer 방식이라고 하면 값에 Bearer 키값 처럼 접두어까지 넣으세요. 저장된 키는 화면에 다시 표시되지 않습니다(칸을 비워 두면 그대로 유지, 지우려면 - 한 글자를 넣고 저장).
고객 연동은 비워 두면 RFC 가 있는 최근 승인 고객으로 시험합니다. 제품처럼 고객이 없는 연동은 계약서 탭의 「요청 예시」를 씁니다.
