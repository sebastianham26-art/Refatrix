# 토요일 수신 보장 — 회차 다시 열기 + 사전 점검 · 2026-10-07

## 왜
Enrique 가 운영 키로 평일에 한 번 받았고, 두 번째 호출은 `ERR_YA_SINCRONIZADO` 로 막혔다(정상 동작).
토요일 05:05 자동 수신이 막히지 않게 하려는 것.

## 결론 먼저 — 토요일은 원래 열린다
주 1회를 세는 열쇠는 **접속창이 열린 그날의 멕시코 날짜**(`period_key`)다.
평일에 받은 회차는 그날 날짜로 기록되므로, **토요일이 되면 새 회차가 열린다.**
막히는 경우는 같은 토요일에 이미 끝까지 받은 때뿐이다.

진짜 위험은 따로 있다 — **시험하느라 접속창 요일·시간을 바꿔 놓았다면** 토요일에 403 이 난다.
아래 점검 명령으로 확인한다.

## 1) 사전 점검 (Railway 백엔드 콘솔, 읽기 전용)
`railway_토요일점검_한줄.txt` 를 통째로 복사해 붙여넣고 Enter.
고객사마다 다음을 보여 주고 마지막에 한 줄로 판정한다.

- 사용 여부 · 운영 키 유무 · 접속창 적용/요일/시간 · 호출 한도 · 대응품번 출처 · 제외 접두어
- 최근 운영 회차 5건
- `✅ 토요일 05:05 수신에 걸리는 것 없음` 또는 `⚠ …` (요일이 토요일이 아님, 키 폐기됨, 그 토요일 회차가 이미 닫힘 등)

## 2) 새 안전장치 — 「이번 회차 다시 열기」
연동관리 → 카탈로그 조회 API → 고객사 선택 → **동기화 회차** 제목 옆 단추.
막힌 고객을 디렉터가 그 자리에서 푼다. 회차 기록만 지우며 제품·가격·키는 건드리지 않는다.
토요일 아침에 혹시 `ERR_YA_SINCRONIZADO` 가 나면 이 단추 한 번이면 끝난다.

- `POST /api/catalog/admin/clients/:id/reset-run` (디렉터 전용, 감사기록 `catalog_run_reset`)
